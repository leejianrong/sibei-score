# Third-party notices — @sibei/engrave

`src/fonts/*.generated.ts` each contain a slice of a music font: its `engravingDefaults`
table, and the metrics and outlines of the 43 glyphs the engraver draws. Both are
generated by `scripts/vendor-music-fonts.ts` from a pinned release and are **not edited
by hand**.

Both fonts are copyright © Steinberg Media Technologies GmbH and licensed under the
**SIL Open Font License, Version 1.1**. The OFL permits redistribution of the font and
of derivatives. Neither generated file carries a Reserved Font Name, and neither is
distributed as a font.

## Bravura — the `normal` face

- <https://github.com/steinbergmedia/bravura>, `redist/OFL.txt`
- `bravura-1.392`. Metrics from `bravura_metadata.json`, outlines verbatim from the
  project's own SVG font.

## Petaluma — the `jazz` face

- <https://github.com/steinbergmedia/petaluma>, `redist/OFL.txt`
- `petaluma-1.065`. Metrics from `petaluma_metadata.json`, outlines read from
  `Petaluma.otf` with `opentype.js` (MIT), a devDependency used only at vendoring time
  and never shipped. Petaluma's redist ships no SVG font, which is why this face is read
  differently from Bravura.

ADR-0027's dependency register lists Bravura under SIL OFL and carries a note about
reading both faces' published metrics directly rather than through a renderer, which is
what ADR-0030 asks for.

## SMuFL glyph names

`scripts/vendor-music-fonts.ts` reads SMuFL's `glyphnames.json` at vendoring time to
resolve glyph names to codepoints, so that no codepoint is transcribed by hand. That
file is **not** redistributed here — only the codepoints it resolved, which are facts
about the SMuFL specification rather than a copyable work.

- <https://github.com/w3c/smufl>, `metadata/glyphnames.json`
